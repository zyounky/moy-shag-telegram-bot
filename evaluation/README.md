# Проверка подбора контекста

`questions.json` содержит 62 формулировки: запуск, маркетинг, финансы, персонал,
маркетплейсы, глоссарий, документы, калькуляторы, перефразирования, отсутствие темы
в базе и неоднозначный запрос. 13 вопросов отмечены для реальной генерации.
Набор составлен вручную по известному каталогу; это проверка регрессий, а не
независимый слепой тест и не доказательство качества для всех вопросов.

До изменения поиска сохраните `assistant_bot/knowledge.py` в доверенную локальную
папку вне репозитория. После изменений сравните обе версии на одном каталоге:

```sh
python scripts/evaluate_context.py --baseline-module /trusted/context_baseline.py --report data/context-offline.json
```

Ожидаемое название материала — приблизительный критерий поиска. Совпадение
названия не доказывает, что внутри контекста есть ответ, а другой материал может
содержать правильное объяснение. Для определения дебиторской задолженности,
например, полезный текст есть внутри статьи «Актив», даже если нет отдельной
карточки с ожидаемым названием. Проверяйте такие случаи по содержимому.

Для оплачиваемого сравнения настройте окружение обычным способом, сохранив
разрешённые tester ID, срок и бюджет. Скрипт сам не читает `.env` и не продлевает
доступ. Затем добавьте `--live`. Выполняется не более 30 запросов одним генератором,
по два на вопрос, с чередованием порядка before/after. Модель, промпт и reasoning
одинаковы. Кеш очищается перед замером, доставка Telegram в задержку не входит.
Для уменьшения эффекта локального прогрева оба каталога загружены заранее.
`--resume` повторно использует результаты только при неизменном тексте источников.
`--spent-requests` учитывает ранее начатые, в том числе прерванные вызовы в том же
общем лимите 30. Перед каждым вызовом счётчик записывается в отчёт; отклонённые
варианты сохраняются в `superseded` и не попадают в итоговые парные показатели.

Сохраняются длительность, время до читаемого текста, токены, структура ответа,
источники и полный выбранный контекст. Отказы и таймауты учитываются отдельно;
время неудачных попыток входит в общие замеры. Один прогон не исключает влияние
нагрузки xAI и серверного кеширования промптов. Результаты следует подтверждать
повторными прогонами в отдельно согласованном бюджете.

Ручная оценка каждой пары:

1. Прямой ответ на вопрос, верные определения, формулы и единицы.
2. Полнота ключевых шагов и сохранение условий из источника.
3. Факты подтверждены выбранными фрагментами, область `content_scope` соблюдена.
4. При недостатке текста — честное ограничение вместо выдуманной инструкции.
5. Выполнимый следующий шаг и проверяемый критерий.

Локальная проверка цитаты и JSON не заменяет эти пункты. Не сводите их к
«проценту правильных ответов» без зафиксированной содержательной разметки.
Отчёты с текстом источников пишутся в игнорируемую `data/`; в Git остаются
методика, синтетические вопросы и код проверки.
