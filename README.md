# «Мой шаг» — Telegram-помощник для предпринимателей

[Заметки релиза](RELEASE_NOTES.md) · [Передача на развёртывание](HANDOFF.md) · [Предыдущие эксперименты](TEAM_UPDATE.md)

Прототип для трека 2 Hack&Change 2026. Предприниматель задаёт вопрос в Telegram и получает ответ по материалам «Альфа-Курса» с учётом ситуации. Он может взять один шаг в работу, поставить напоминание со ссылкой на исходный материал и отметить результат. Если что-то помешало, бот уточняет препятствие и подбирает выполнимый шаг. Текущий шаг остаётся в работе до завершения или подтверждённой замены.

[Презентация проекта и сценарий проверки](docs/moy-shag.pdf)

## Попробовать без токена и исходной базы

Для консольного демо нужны Python 3.11+ и зависимости проекта.

```sh
python -m pip install -r requirements.txt
python -m assistant_bot --demo
```

Выберите язык командой `/click lang:ru` или `/click lang:en`. Затем задайте вопрос, например «Как оценить эффективность рекламы кофейни?» или «How do I measure ad performance for my coffee shop?». Команды `/click …` заменяют кнопки Telegram.

Чтобы снова увидеть первый экран без сброса существующего диалога, задайте для демо новый путь к SQLite через `STATE_PATH`. В PowerShell, например, выполните `$env:STATE_PATH = Join-Path $env:TEMP ("moy-shag-" + [guid]::NewGuid() + ".db")` перед запуском.

В Telegram отправьте `/start`, выберите язык и откройте «Помощь» или «Что я умею» из меню. `/menu` возвращает в меню, `/step` открывает задачу, `/profile` открывает «Мой бизнес», `/remind` создаёт напоминание, `/reminders` показывает расписание, `/cancel` отменяет текущий ввод. Язык можно сменить через `/language`. Меню и напоминания доступны на обоих языках. Поиск понимает типовые вопросы на английском, а материалы курса и советы без внешней модели могут быть на русском.

Для проверки в Telegram со своим ботом скопируйте `env.example` в `.env`, заполните `BOT_TOKEN`, задайте `DEMO_MODE=true` и выполните `docker compose up --build`.

## Запуск с каталогом кейса

Понадобятся Docker с Compose, токен Telegram-бота и официальная выгрузка. Compose сам подготовит каталог перед запуском бота.

1. Возьмите `alfa_course_hackathon.backup` по ссылке из приложения 1 к кейсу. Создайте папку `data/` в корне проекта и положите дамп в неё.
2. Создайте бота через [@BotFather](https://t.me/BotFather). Скопируйте `env.example` в `.env` и заполните `BOT_TOKEN`. Для проверки используйте отдельный токен и один экземпляр приложения.
3. Из корня проекта выполните:

   ```sh
   docker compose up --build
   ```

4. Откройте своего бота в Telegram и отправьте `/start`. Для остановки используйте `docker compose down`. Именованный том `runtime` хранит данные после остановки и повторного запуска.

Входящие порты не публикуются. Бот устанавливает исходящие HTTPS-соединения с Telegram Bot API через long polling. Внешний ключ модели для основного сценария не требуется.

### Переменные окружения

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather. Храните его в локальном `.env`. |
| `CATALOG_PATH` | Путь к подготовленному JSONL-каталогу. В контейнере по умолчанию `/app/catalog/catalog.jsonl`. |
| `STATE_PATH` | Путь к SQLite-базе. В контейнере по умолчанию `/app/runtime/state.db`. |
| `DEMO_MODE` | По умолчанию `false`. Режим проверки на синтетических материалах включается явно. |
| `OLLAMA_URL` | Необязательный адрес локальной Ollama. Оставьте пустым для запуска с автономным ранжированием. |
| `OLLAMA_MODEL` | Имя установленной в локальной Ollama модели. Заполните при использовании `OLLAMA_URL`. |
| `LLM_PROVIDER` | `none` (по умолчанию), `xai` или `openrouter`. Внешняя генерация ответа по найденным фрагментам. |
| `LLM_MODEL` | Для xAI по умолчанию `grok-4.7`; для OpenRouter — `anthropic/claude-sonnet-5.5`. |
| `XAI_API_KEY` | Ключ xAI, используется только с `LLM_PROVIDER=xai`. |
| `OPENROUTER_API_KEY` | Ключ OpenRouter, используется только с `LLM_PROVIDER=openrouter`. |
| `LLM_TIMEOUT_SECONDS` | Таймаут одного запроса, 1–60 секунд; по умолчанию 30. Автоматических повторов нет. |
| `LLM_ALLOW_CASE_DATA` | По умолчанию `false`: внешний API работает только с синтетическим демокаталогом. |
| `LLM_TEST_CHAT_IDS` | Разрешённые Telegram chat ID через запятую для тестирования официального каталога. Без списка такие запросы во внешний API не отправляются. |
| `LLM_TEST_EXPIRES_AT` | Конец тестовой сессии в ISO 8601 с часовым поясом, например `2026-11-14T21:00:00+03:00`. Обязателен для Telegram-тестов официального каталога. |
| `LLM_MAX_REQUESTS` | Лимит внешних вызовов на один запуск, по умолчанию 30, максимум 100. Ошибочные вызовы тоже учитываются. |
| `LLM_STREAM` | По умолчанию `true`. Показывать предварительный ответ по мере поступления. |
| `LLM_BUDGET_PATH` | Необязательная SQLite для сохранения лимита между перезапусками в том же тестовом окне. Compose и серверная служба включают её по умолчанию. |

### Grok сейчас, Sonnet позже

Без внешней модели бот продолжает работать по прежним правилам. Для тестирования генерации на синтетических данных создайте `.env` из `env.example` и задайте:

```dotenv
DEMO_MODE=true
LLM_PROVIDER=xai
LLM_MODEL=grok-4.7
XAI_API_KEY=ваш_локальный_ключ
LLM_ALLOW_CASE_DATA=false
```

API-ключ создаётся в [консоли xAI](https://console.x.ai/). Не добавляйте ключ в Git, скриншоты или переписку. У API должны быть доступ к указанной модели и средства/квота. Актуальный интерфейс — [Responses API](https://docs.x.ai/developers/model-capabilities/text/generate-text), структурированный ответ — [JSON Schema](https://docs.x.ai/developers/model-capabilities/text/structured-outputs).

После заполнения `BOT_TOKEN` запустите `docker compose up --build`. Для консольного теста без Telegram:

```sh
docker compose run --build --rm --no-deps bot --demo
```

Отдельная проверка ключа и реального ответа модели (один оплачиваемый запрос на синтетических данных, токен Telegram и официальный каталог не нужны):

```sh
docker compose run --build --rm --no-deps bot --llm-check
```

Код выхода 0 означает, что модель вернула ответ с проверенной структурой и цитатой. Ошибка API или валидации даёт код 2; локальная подстановка здесь не считается успехом. Это не оценка качества всей консультации.

Compose читает `.env` автоматически. При запуске обычным `python -m assistant_bot --demo` приложение **не читает `.env`**: предварительно задайте эти переменные в окружении. Не используйте контейнерные `CATALOG_PATH` и `STATE_PATH` как локальные пути Windows. `--check` проверяет каталог/SQLite без сетевого вызова и не подтверждает доступность API.

Внешняя модель получает вопрос, краткие поля стадии, сферы и цели, препятствие и до трёх найденных фрагментов. Для каждого фрагмента передаются тип и область содержания. ID чата, полная история, Telegram-токен, платные карточки и URL остаются в приложении.

Единый локальный фильтр проверяет вопрос, профиль, препятствие, заголовки и выдержки. Правила маскируют распознаваемые email, телефоны, ключи и номера документов, сохраняя деловые суммы, проценты и даты. Явные раскрытия имени или адреса и ошибки проверки блокируют отправку. Отклонённый ввод не расходует бюджет API. Цитата проверяется по той очищенной выдержке, которую получила модель. Фильтр не требует модели NER или сетевого сервиса. Он покрывает известные форматы, а неизвестные, замаскированные или косвенные персональные сведения могут остаться нераспознанными. Для демонстрации используйте синтетические профили.

Для работы с официальным каталогом оставляйте `LLM_ALLOW_CASE_DATA=false`, пока не проверено право передавать соответствующие фрагменты выбранному сервису. Только при наличии такого права выставляйте `true`. Исходный дамп никогда не отправляется целиком. Проверка признака публичности статьи не заменяет проверку условий внешней обработки.

Тестовый запуск в Telegram с официальным каталогом дополнительно требует `LLM_TEST_CHAT_IDS` и будущую `LLM_TEST_EXPIRES_AT`. По истечении времени или лимита вызовов остаётся подборка материалов с явным сообщением, что консультация не активна; чужие чаты не отправляются внешней модели. Эти настройки ограничивают тестовую сессию, а не являются готовой моделью согласий для публичного пилота. При `LLM_BUDGET_PATH` счётчик попыток сохраняется между перезапусками для того же провайдера, списка тестеров и срока. Изменение срока или списка не должно использоваться для обхода лимита. Без этого пути счётчик действует только в памяти процесса.

Модель собирает связный ответ из нескольких найденных фрагментов, предлагает шаг и критерий. Приложение проверяет структуру, индексы использованных источников, цитату главного источника, размеры полей и отсутствие URL/HTML. Ссылки берутся из каталога. Проверка цитаты не доказывает правильность всех утверждений генератора: необходим отдельный набор вопросов с ручной оценкой. При нехватке сведений бот просит уточнение; при таймауте или ошибке сообщает, что ответ не подготовлен, и предлагает найденные материалы. Автоматической подмены консультации случайной выдержкой нет. Модель не вызывается при отсутствии фрагментов. Напоминания создаёт и отправляет код, внешний API ими не управляет.

### Скорость ответа

`LLM_STREAM=true` (по умолчанию) включает постепенный показ текста в Telegram. Предварительный ответ помечен «Ответ формируется…»; кнопки появляются после получения и проверки полного результата. Показ начинается только после проверки индексов источников и дословной опорной цитаты. Такая проверка не доказывает каждое утверждение ответа. При обрыве потока предварительный текст заменяется сообщением об ошибке. Чтобы отключить поток, задайте `LLM_STREAM=false`.

Компактный промпт сохраняет до трёх источников по 3600 символов. Точные варианты опорной цитаты подготавливаются локально; длины полей ограничивает JSON Schema. Модель и режим рассуждения `low` сохранены. Приоритетный платный тариф не включён.

Успешный ответ кешируется в памяти процесса на 5 минут, максимум 32 записи. Ключ включает чат, вопрос, профиль, препятствие, модель, промпт и источники. Изменение контекста требует нового запроса. Ограничения доступа и срока теста проверяются до кеша; после перезапуска кеш пуст. Повтор из кеша не расходует запрос API. В журналах фиксируются длительность генерации, время до предварительного текста и попадание в кеш без содержания вопроса.

В сравнении подбора контекста на 62 вопросах медианный объём фрагментов сократился с 6248 до 3002 символов. В 13 парных генерациях медиана полного ожидания изменилась с 15,7 до 16,4 секунды, а 90-й процентиль — с 29,4 до 18,8 секунды. На 10 парах, где обе версии дали ответ, медиана стала 17,7 вместо 15,8 секунды. Таким образом, сокращение типичного ожидания не доказано; улучшились объём контекста и долгие задержки. Нагрузка API и рассуждение модели дают большой разброс. Это один небольшой прогон, без доставки Telegram; [методика и ограничения](evaluation/README.md). Повтор из локального кеша ранее занимал менее 2 мс без доставки Telegram.

### Расширенный каталог и поиск

Импорт обрабатывает открытые статьи, глоссарий, документы, описания вебинаров, подкастов и калькуляторов, карточки курсов и текстовые блоки доступных бесплатных уроков. Документы представлены описанием и блоками карточки, а не прочитанными скачиваемыми файлами. Аудио и видео не транскрибируются, калькулятор не исполняется. Наличие карточки не означает, что бот видел полное содержимое материала.

Удалённые, закрытые и `NoIndex`-материалы исключаются. Для урока проверяются все родительские курсы и привязки: положительная цена, платный тариф, подписка, закрытая привязка или отложенный доступ исключают текст. Полный текст курса не индексируется. Пользовательские таблицы не читаются.

Локальный поиск использует русскую морфологию pymorphy3, BM25, вес заголовка/раздела, ограниченные тематические синонимы и проверки конкретных платформ/налоговых режимов. Составные темы вроде «бизнес-план» сохраняются. Контекст расширяется соседними блоками исходного материала. Это лексический поиск с нормализацией и правилами, а не нейросетевые эмбеддинги. Проверять качество нужно на новых формулировках, особенно при неоднозначных запросах.

Для инструкции приоритет получают нумерованные шаги, для определения — разделы с формулами и соседними условиями. Более далёкие релевантные разделы могут заменить случайных соседей. Основной источник ограничен 3600 символами, дополнительные — 1600 каждый; слабые дополнительные источники исключаются. Прямое определение из глоссария используется самостоятельно. Текст извлекается локально без дополнительной LLM и располагается в исходном порядке. Такое сокращение не гарантирует сохранения всех нюансов; проверка формул и полноты входит в [методику сравнения на 62 вопросах](evaluation/README.md).

Для отдельного Linux-сервера подготовлены [unit systemd и порядок переноса](deploy/README.md), с отдельным пользователем, сохранением состояния и постоянным лимитом API-попыток.

Для проверки полного каталога попробуйте «Как составить бизнес-план?», «Как удержать сотрудников?», «NPS», «ROI» или «Нужен шаблон соглашения о неразглашении». Точный однозначный термин бот определяет локально по глоссарию. Команда `python -m assistant_bot --check` выводит фактические количества по типам. Локальная пересборка из предоставленной выгрузки дала 1 428 материалов, из них 1 395 с текстом или доступным описанием.

Будущий переход на Sonnet через OpenRouter требует изменения конфигурации:

```dotenv
LLM_PROVIDER=openrouter
LLM_MODEL=anthropic/claude-sonnet-5.5
OPENROUTER_API_KEY=ваш_локальный_ключ
```

Используется `https://openrouter.ai/api/v1/responses`, запросы имеют `store=false`. Для OpenRouter запрещены маршруты с разрешённым сбором данных и автоматическое переключение провайдера. Это может ограничить доступность маршрута. Настройка не отменяет условия хранения сервисов или региональные правила модели; возможность использования необходимо проверить для своего аккаунта. [Модель](https://openrouter.ai/anthropic/claude-sonnet-5.5), [региональные условия Anthropic](https://www.anthropic.com/legal/supported-regions).

Для Grok и Sonnet используется один базовый промпт и контракт ответа. После смены модели повторно оцените правильность, отказы, стиль русского языка, задержки и расход токенов на одинаковом наборе вопросов. Ключи и доступность провайдеров не входят в локальные тесты:

```sh
python -m unittest discover -s tests -v
```

### Быстрая проверка без токена

```sh
docker compose run --build --rm --no-deps bot --demo --check
docker compose run --rm --no-deps bot --demo
```

Первая команда проверяет загрузку синтетического каталога и создание SQLite. Вторая открывает консольный диалог. Введите «Как оценить эффективность рекламы кофейни?» и копируйте команды `/click …` рядом с кнопками. Для проверки доставки по расписанию используйте запуск в Telegram.

### Подготовка и запуск без Docker

Для локальной подготовки нужны Python 3.11+ и `pg_restore` версии 17+. Готовый `data/catalog.jsonl` можно использовать и при запуске через Compose.

```sh
python scripts/catalog_build.py --backup data/alfa_course_hackathon.backup --output data/catalog.jsonl
python -m pip install -r requirements.txt
python -m assistant_bot
```

Перед запуском задайте `BOT_TOKEN` в окружении. Пути по умолчанию на хосте — `data/catalog.jsonl` и `runtime/state.db`.

Команда `python -m assistant_bot --check` проверяет каталог и SQLite без токена. Команда `python -m assistant_bot --console` открывает диалог с подготовленным каталогом.

### Необязательная локальная модель

Для локального запуска с Ollama задайте `OLLAMA_URL=http://localhost:11434`. В Docker Desktop используйте `OLLAMA_URL=http://host.docker.internal:11434`, если контейнеру доступен сервер на хосте. Укажите имя установленной локальной модели в `OLLAMA_MODEL` и включите на сервере Ollama режим `OLLAMA_NO_CLOUD=1`. [Настройки локальной Ollama](https://docs.ollama.com/faq)

## Как проверить основные сценарии

1. **Ответ по базе.** Спросите «Как оценить эффективность рекламы кофейни?». Проверьте следующий шаг и переход по кнопке «Открыть источник». В официальном каталоге вопрос «Как вести налоговый учёт на УСН при продажах на маркетплейсе?» показывает рекомендацию платного курса с кратким описанием и ссылкой на карточку.
2. **Уточнение и пробел в базе.** Напишите «Маркетинг» и уточните, чего хотите добиться. Через «Мой бизнес» можно отдельно выбрать стадию и сферу и посмотреть часовой пояс. На вопрос «Сколько лун у Юпитера?» бот сообщает о пробеле в базе.
3. **Возврат к конкретному шагу.** Совет можно снова открыть через «Моя задача». Если там уже есть задача, откройте «Последний совет». Нажмите «Начать задачу» → «Напомнить» → «Через минуту» → «Один раз». Подтвердите время и дождитесь сообщения. Через «Моя задача» отметьте результат или нажмите «Не получается» и опишите затруднение. Бот подберёт следующий материал с учётом уточнения, если найдёт его.
4. **Повтор и управление.** Отправьте `/remind`, выберите «Работа» и введите название и дату этого события. Выберите ежедневный или еженедельный повтор и подтвердите. Через `/reminders` измените частоту, затем отключите напоминание. Перезапустите контейнер, чтобы проверить сохранение активных напоминаний.

Набор из 36 сценариев и команды локального прогона есть в [разделе оценки](evaluation/README.md). CI запускает тесты и чистую сборку Docker на синтетических данных. Для этой проверки ключи, Telegram и официальный дамп не нужны. [GitHub Actions](https://github.com/zyounky/moy-shag-telegram-bot/actions/workflows/ci.yml)

## Архитектура

- **Импорт.** Локальный скрипт читает только таблицы контента и прав доступа из резервной копии PostgreSQL, собирает JSONL-каталог с типами и областью содержания. Платные и подписочные курсы представлены карточками с метаданными и ссылками.
- **Консультации.** Морфология и BM25 находят источники; приложение добавляет соседний контекст. Сфера, стадия и текущая задача бизнеса используются при подборе. Внешние xAI/OpenRouter формируют ответ, шаг и критерий через общий адаптер с локальной валидацией. При недостатке оснований или ошибке бот обозначает это, а не выдаёт выдержку за ответ. Ссылки подставляет приложение из каталога.
- **Напоминания.** Приложение хранит в SQLite контекст, подтверждённое расписание, статус отправки и связанный материал. Тот же процесс бота отправляет сообщения по расписанию.

- **Параллельная работа.** Четыре обработчика обслуживают разные чаты независимо; внутри одного чата сохраняется порядок. В очереди максимум восемь запросов, не более двух на чат, включая выполняемый. При переполнении бот просит дождаться предыдущих ответов. Статус, уточнение и метрики LLM изолированы по обработчику; кеш и бюджет защищены от одновременного доступа. При SIGTERM/SIGINT приложение прекращает приём и завершает принятые запросы; аварийное завершение не обеспечивает сохранность очереди в памяти. Серверный unit даёт до 210 секунд на завершение.

Дамп, производные данные, локальная база и `.env` хранятся вне Git. Контейнер подготовки каталога получает исходные данные через монтирование только для чтения и работает без сети. Бот читает подготовленный каталог из отдельного тома.

## Как измерить эффект после внедрения

Перед пилотом случайно распределить пользователей между обычным опытом платформы и предложением подключить бота. Основная метрика — доля назначенных в группу пользователей, купивших образовательный продукт за 30 дней. Дополнительные — доля повторных визитов и среднее число активных дней за первую неделю. Для диагностики измерять принятие задачи, создание и доставку напоминания, отметку о выполнении и отключение уведомлений. Сравнивать группы по исходному назначению, заранее определить размер выборки и длительность.

Прототип хранит текущий статус задачи и напоминаний в SQLite для работы сервиса. События эксперимента и сверка покупок требуют интеграции с аналитикой «Альфа-Курса» и согласованной связки пользователей. Кнопка «Сделано» фиксирует самоотметку пользователя. Покупку и визит подтверждают события платформы. Реальный эксперимент ещё не запускался.

## Ограничения прототипа

Покрытие ответов зависит от выгрузки и качества совпадения с фрагментами. Пользователь подтверждает дату бизнес-события сам. Прототип работает с одним процессом отправки напоминаний и одним локальным хранилищем. Для демонстрации используйте тестовые профили. Результаты эксперимента по возвратам и покупкам можно получить после подключения к аналитике платформы.
