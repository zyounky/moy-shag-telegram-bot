# Проверка качества ответов и сценариев

## Текущий набор

`scenarios.json` содержит 36 сценариев. 24 проверяют подбор источников, уточнения
и пробелы в базе. Ещё 12 проверяют логику бота, включая уточнения в несколько
ходов, три стадии бизнеса, недостаток данных для оценки рекламы, напоминания,
недоступность API, исчерпанный бюджет и карточку без основного текста.

Из корня репозитория после установки `requirements.txt`:

```sh
python -m unittest discover -s tests -v
python scripts/evaluate_scenarios.py --report data/release-synthetic.json
python scripts/evaluate_scenarios.py --catalog data/catalog.jsonl --report data/release-official.json
```

Третья команда нужна только при наличии локального каталога кейса. Каталог готовится
по инструкции в основном README. В первом режиме поиска используются учебный каталог
бота и синтетические дополнения из `synthetic_catalog.jsonl`. Логика диалога и отказов
в обоих режимах проверяется на учебных данных. Заглушки моделируют отказ транспорта
и учитывают попытки, настоящий Telegram-бот и внешний API скрипт не вызывает.
Результат поиска зависит от версии каталога. Скрипт возвращает статус 1 при
несовпадении с ожиданиями, а JSON сохраняет идентификаторы сценариев и диагностические
поля без текста из каталога, ответов модели и ссылок.

## Как читать результаты

| Что проверяем | Что записываем |
| --- | --- |
| Автотесты и логика диалога | Общее число и число успешных сценариев. Отдельно проверяем состояние, кнопки, отказ API, бюджет и доставку в тестовый приёмник. |
| Поиск | Попадание ожидаемого заголовка на первое место или в первые три, решение об уточнении, отсутствие ответа, наличие карточки и область доступного содержания. Для карточки без текста не считаем описание полным материалом. |
| Локальная задержка | Медиана и 90-й процентиль времени `Catalog.search()` по 24 запросам после построения индекса. Замер включает порядок запросов этого прогона. |
| Реальная генерация | Нужен отдельный согласованный прогон. В offline-отчёте отмечается `not_run`, число сетевых вызовов равно нулю. |

Совпадение заголовка служит сигналом для проверки: ожидаемый заголовок может
попасть в результаты без нужного фрагмента, а новый релевантный материал может
не совпасть с разметкой. Проверяйте такие случаи по содержанию. Значения задержки
локального поиска не измеряют время генерации и доставки Telegram.

## Рубрика для реальных генераций

В отдельном разрешённом прогоне сохраним локально идентификатор сценария, версию
кода и каталога, модель и настройку reasoning, статус ответа, наличие кеша,
время до первого читаемого текста и до завершения. Зафиксируем оценку по каждому
критерию и короткое обоснование. Шкала 0–2: 0 — ошибка или пропуск, 1 — частично,
2 — выполнено. Для неприменимого критерия используем «н/п». Сетевые ошибки,
исчерпание лимита и честное указание на пробел в источнике отмечаем отдельными
статусами. Сравниваем задержки на одинаковом наборе отдельно для обычных ответов,
кешированных повторов и отказов.

| Критерий | Что проверяет человек |
| --- | --- |
| Исходный вопрос | Ответ решает заданную задачу с учётом уточнений. |
| Ключевые факты | Существенные шаги, оговорки и условия из источника сохранены. |
| Подтверждение | Каждый существенный факт подтверждён доступным фрагментом, ссылки ведут к указанным материалам. |
| Формулы и единицы | В расчёте верны формула, входные величины, период и размерность. |
| Следующее действие | Действие выполнимо для текущей стадии бизнеса и имеет проверяемый результат. |
| Границы содержания | Краткая карточка не выдаётся за полный шаблон, закрытые сведения не раскрываются, при пробеле бот говорит об ограничении. |

Метки `review` в наборе поясняют, что проверять в конкретном сценарии. Прохождение
JSON Schema и совпадение цитаты проверяют структуру и происхождение цитаты. Факты,
полноту и пригодность действия оценивают отдельно. Исходные материалы, диалоги,
полные отчёты с генерациями и ключи остаются за пределами Git.

Шаблон строки для локального протокола:

| --- | --- | --- | --- | --- | --- | --- | --- | --- |

## Историческое сравнение контекста, 14 ноября 2026

[Результаты сравнения 14 ноября](results-2026-11-14.md) относятся к прежней
реализации. Они приведены как история и не являются оценкой текущего набора
из 36 сценариев.

`questions.json` содержит 62 формулировки: запуск, маркетинг, финансы, персонал,
маркетплейсы, глоссарий, документы, калькуляторы, перефразирования, отсутствие темы
в базе и неоднозначный запрос. 13 вопросов отмечены для реальной генерации.
Набор составлен вручную по известному каталогу; это проверка регрессий, а не
независимый слепой тест и не доказательство качества для всех вопросов.

До изменения поиска сохраните `assistant_bot/knowledge.py` в доверенную локальную
папку вне репозитория. После изменений сравните обе версии на одном каталоге:

```sh
python scripts/evaluate_context.py --baseline-module /trusted/context_baseline.py --report data/context-offline.json
```

Ожидаемое название материала — приблизительный критерий поиска. Совпадение
названия не доказывает, что внутри контекста есть ответ, а другой материал может
содержать правильное объяснение. Для определения дебиторской задолженности,
например, полезный текст есть внутри статьи «Актив», даже если нет отдельной
карточки с ожидаемым названием. Проверяйте такие случаи по содержимому.

Для оплачиваемого сравнения настройте окружение обычным способом, сохранив
разрешённые tester ID, срок и бюджет. Скрипт сам не читает `.env` и не продлевает
доступ. Затем добавьте `--live`. Выполняется не более 30 запросов одним генератором,
по два на вопрос, с чередованием порядка before/after. Модель, промпт и reasoning
одинаковы. Кеш очищается перед замером, доставка Telegram в задержку не входит.
Для уменьшения эффекта локального прогрева оба каталога загружены заранее.
`--resume` повторно использует результаты только при неизменном тексте источников.
`--spent-requests` учитывает ранее начатые, в том числе прерванные вызовы в том же
общем лимите 30. Перед каждым вызовом счётчик записывается в отчёт; отклонённые
варианты сохраняются в `superseded` и не попадают в итоговые парные показатели.

Сохраняются длительность, время до читаемого текста, токены, структура ответа,
источники и полный выбранный контекст. Отказы и таймауты учитываются отдельно;
время неудачных попыток входит в общие замеры. Один прогон не исключает влияние
нагрузки xAI и серверного кеширования промптов. Результаты следует подтверждать
повторными прогонами в отдельно согласованном бюджете.

Ручная оценка каждой пары:

1. Прямой ответ на вопрос, верные определения, формулы и единицы.
2. Полнота ключевых шагов и сохранение условий из источника.
3. Факты подтверждены выбранными фрагментами, область `content_scope` соблюдена.
4. При недостатке текста — честное ограничение вместо выдуманной инструкции.
5. Выполнимый следующий шаг и проверяемый критерий.

Локальная проверка цитаты и JSON не заменяет эти пункты. Не сводите их к
«проценту правильных ответов» без зафиксированной содержательной разметки.
Отчёты с текстом источников пишутся в игнорируемую `data/`; в Git остаются
методика, синтетические вопросы и код проверки.
