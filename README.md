# «Мой шаг» — Telegram-помощник для предпринимателей

Прототип для трека 2 Hack&Change 2026. Предприниматель задаёт вопрос в Telegram и получает ответ по материалам «Альфа-Курса» с учётом ситуации. Он может взять один шаг в работу, поставить напоминание со ссылкой на исходный материал и отметить результат. Если что-то помешало, бот уточняет препятствие и подбирает выполнимый шаг. Текущий шаг остаётся в работе до завершения или подтверждённой замены.

[Презентация проекта и сценарий проверки](docs/moy-shag.pdf)

## Попробовать без токена и исходной базы

Для консольного демо нужны Python 3.11+ и зависимости проекта.

```sh
python -m pip install -r requirements.txt
python -m assistant_bot --demo
```

Введите «Как оценить эффективность рекламы кофейни?». Под ответом появятся команды `/click …`, которые заменяют кнопки Telegram. В репозитории есть синтетический каталог для этого режима.

Для проверки в Telegram со своим ботом скопируйте `env.example` в `.env`, заполните `BOT_TOKEN`, задайте `DEMO_MODE=true` и выполните `docker compose up --build`.

## Запуск с каталогом кейса

Понадобятся Docker с Compose, токен Telegram-бота и официальная выгрузка. Compose сам подготовит каталог перед запуском бота.

1. Возьмите `alfa_course_hackathon.backup` по ссылке из приложения 1 к кейсу. Создайте папку `data/` в корне проекта и положите дамп в неё.
2. Создайте бота через [@BotFather](https://t.me/BotFather). Скопируйте `env.example` в `.env` и заполните `BOT_TOKEN`. Для проверки используйте отдельный токен и один экземпляр приложения.
3. Из корня проекта выполните:

   ```sh
   docker compose up --build
   ```

4. Откройте своего бота в Telegram и отправьте `/start`. Для остановки используйте `docker compose down`. Именованный том `runtime` хранит данные после остановки и повторного запуска.

Входящие порты не публикуются. Бот устанавливает исходящие HTTPS-соединения с Telegram Bot API через long polling. Внешний ключ модели для основного сценария не требуется.

### Переменные окружения

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather. Храните его в локальном `.env`. |
| `CATALOG_PATH` | Путь к подготовленному JSONL-каталогу. В контейнере по умолчанию `/app/catalog/catalog.jsonl`. |
| `STATE_PATH` | Путь к SQLite-базе. В контейнере по умолчанию `/app/runtime/state.db`. |
| `DEMO_MODE` | По умолчанию `false`. Режим проверки на синтетических материалах включается явно. |
| `OLLAMA_URL` | Необязательный адрес локальной Ollama. Оставьте пустым для запуска с автономным ранжированием. |
| `OLLAMA_MODEL` | Имя установленной в локальной Ollama модели. Заполните при использовании `OLLAMA_URL`. |

### Быстрая проверка без токена

```sh
docker compose run --build --rm --no-deps bot --demo --check
docker compose run --rm --no-deps bot --demo
```

Первая команда проверяет загрузку синтетического каталога и создание SQLite. Вторая открывает консольный диалог. Введите «Как оценить эффективность рекламы кофейни?» и копируйте команды `/click …` рядом с кнопками. Для проверки доставки по расписанию используйте запуск в Telegram.

### Подготовка и запуск без Docker

Для локальной подготовки нужны Python 3.11+ и `pg_restore` версии 17+. Готовый `data/catalog.jsonl` можно использовать и при запуске через Compose.

```sh
python scripts/catalog_build.py --backup data/alfa_course_hackathon.backup --output data/catalog.jsonl
python -m pip install -r requirements.txt
python -m assistant_bot
```

Перед запуском задайте `BOT_TOKEN` в окружении. Пути по умолчанию на хосте — `data/catalog.jsonl` и `runtime/state.db`.

Команда `python -m assistant_bot --check` проверяет каталог и SQLite без токена. Команда `python -m assistant_bot --console` открывает диалог с подготовленным каталогом.

### Необязательная локальная модель

Для локального запуска с Ollama задайте `OLLAMA_URL=http://localhost:11434`. В Docker Desktop используйте `OLLAMA_URL=http://host.docker.internal:11434`, если контейнеру доступен сервер на хосте. Укажите имя установленной локальной модели в `OLLAMA_MODEL` и включите на сервере Ollama режим `OLLAMA_NO_CLOUD=1`. [Настройки локальной Ollama](https://docs.ollama.com/faq)

## Как проверить основные сценарии

1. **Ответ по базе.** Спросите «Как оценить эффективность рекламы кофейни?». Проверьте следующий шаг и переход по кнопке «Открыть источник». В официальном каталоге вопрос «Как вести налоговый учёт на УСН при продажах на маркетплейсе?» показывает рекомендацию платного курса с кратким описанием и ссылкой на карточку.
2. **Уточнение и пробел в базе.** Напишите «Маркетинг». Ответьте на уточнение о стадии бизнеса или нужном результате. Через `/profile` проверьте или измените стадию. На вопрос «Сколько лун у Юпитера?» бот сообщает о пробеле в базе.
3. **Возврат к конкретному шагу.** После ответа нажмите «Взять шаг в работу» → «Напомнить об этом шаге» → «Через минуту» → «Один раз». Подтвердите время и дождитесь сообщения. Через «Мой шаг» отметьте результат или нажмите «Есть препятствие» и опишите затруднение. Бот подберёт следующий материал с учётом уточнения, если найдёт его.
4. **Повтор и управление.** Отправьте `/remind`, выберите «Бизнес-событие» и введите название и дату этого события. Выберите ежедневный или еженедельный повтор и подтвердите. Через `/reminders` измените частоту, затем отключите напоминание. Перезапустите контейнер, чтобы проверить сохранение активных напоминаний.

## Архитектура

- **Импорт.** Локальный скрипт читает резервную копию PostgreSQL и собирает компактный JSONL-каталог. В индекс ответов входят разрешённые опубликованные материалы. Платные курсы представлены карточками с метаданными и ссылками.
- **Консультации.** Поиск привязывает ответ к фрагментам каталога. Сфера, стадия и текущая задача бизнеса уточняются по ходу диалога и используются при выборе следующего шага. Локальная модель, если подключена, выбирает из найденных вариантов. Ссылки подставляет приложение из каталога.
- **Напоминания.** Приложение хранит в SQLite контекст, подтверждённое расписание, статус отправки и связанный материал. Тот же процесс бота отправляет сообщения по расписанию.

Дамп, производные данные, локальная база и `.env` хранятся вне Git. Контейнер подготовки каталога получает исходные данные через монтирование только для чтения и работает без сети. Бот читает подготовленный каталог из отдельного тома.

## Как измерить эффект после внедрения

Случайно распределить пользователей между базовым опытом платформы и предложением воспользоваться ботом. Сравнить долю пользователей хотя бы с одним повторным визитом за 7 дней и среднее число активных дней. Для бизнес-эффекта сравнить конверсию в покупку курса в одинаковом заранее выбранном окне. Переходы из бота к материалу, отключения напоминаний и доля вопросов без ответа помогут понять причины результата.

## Ограничения прототипа

Покрытие ответов зависит от выгрузки и качества совпадения с фрагментами. Пользователь подтверждает дату бизнес-события сам. Прототип работает с одним процессом отправки напоминаний и одним локальным хранилищем. Для демонстрации используйте тестовые профили. Результаты эксперимента по возвратам и покупкам можно получить после подключения к аналитике платформы.
